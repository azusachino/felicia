# ADR 0014: Persist Import Runs and Canonical Observation History

## Decision

Persist source synchronization metadata in `import_runs` and canonical
observation snapshots in `source_observations`. Observation rows contain only
the normalized kind, source identity, observed time, confidence, canonical JSON
payload, change flag, and orphan marker. Provider DTOs remain inside adapters.

Observation history is append-oriented per import run and uniquely keyed within
that run by source identity. Recording an identity compares its canonical
payload with the most recent prior observation. A run can mark source
identities not seen in the current source response as orphaned; authored
mementos are not modified by this operation.

Import and observation IDs use UUIDv7 when generated by the repository, with
the database migration retaining the same UUIDv7 default used by existing
Felicia tables.

## Consequences

- Re-import changes and source disappearance are inspectable independently of
  authored content.
- The canonical payload is explicit JSON and can evolve with observation kind
  versioning without persisting provider response shapes.
- Run finalization and orphan marking are separate operations until aggregate
  transaction/concurrency work is completed in task 6.
