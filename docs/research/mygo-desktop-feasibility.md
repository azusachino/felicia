# MyGo desktop feasibility

Source assessment of Felicia `8d512df6b467fccaeb6e7cc749524e2f0f7ffcde` and [MyGo source](https://github.com/egoist/mygo/tree/cbee0b218286ab533aa005ac621a4e34ab6b1422) at `cbee0b218286ab533aa005ac621a4e34ab6b1422`. No prototype or runtime test was performed.

## Conclusion

A shell migration is plausible without rewriting the Svelte UI or Go domain: MyGo supports the system webview and registering an `http.Handler` for its own `mygo` scheme. Felicia already routes the embedded UI and admin API through `DesktopHandler`, an `http.Handler`. This needs an actual macOS spike before treating it as equivalent, especially for request bodies, window behavior and security. The owner clarified that Liquid Glass is not a hard requirement. A full native-Go UI is a separate, much larger rewrite.

## Mapping and risks

- `apps/felicia-desktop/main.go` composes SQLite, runtime, assets and the existing handler, then creates the Wails window; `go.mod` pins Wails v3 beta.24. The backend and `handler.go` are not intrinsically Wails APIs.
- [MyGo frontend documentation](https://github.com/egoist/mygo/blob/cbee0b218286ab533aa005ac621a4e34ab6b1422/docs/frontend.md#custom-protocols) says `Protocol.Handle` accepts `http.Handler` and handling `mygo` replaces its frontend handler. This is a promising way to preserve same-origin relative `/api` requests and the no-admin-TCP-listener boundary. Verify actual WebKit POST bodies, response headers, errors, cancellation and embedded assets, not just a GET. Retain the separate read-only loopback preview behavior.
- [MyGo desktop APIs](https://github.com/egoist/mygo/blob/cbee0b218286ab533aa005ac621a4e34ab6b1422/docs/native.md#dialogs) provide window-attached file and directory dialogs; map Felicia's callbacks and cancellation semantics.
- `apps/felicia-desktop/window_chrome_darwin.go` requests hidden-inset title bar and Liquid Glass. MyGo documents hidden-inset title bars and vibrancy, but visual equivalence to Wails' Liquid Glass is not established. `apps/felicia-admin/src/App.svelte` detects Wails via user agent and CSS uses `--wails-draggable`; adapt both to MyGo's [runtime and `--app-region`](https://github.com/egoist/mygo/blob/cbee0b218286ab533aa005ac621a4e34ab6b1422/docs/frontend.md#custom-title-bars).
- MyGo treats its custom-scheme pages as trusted, allowing access to bound methods and custom-scheme responses; its docs warn that even untrusted pages can issue requests without reading responses. Audit navigation, user-generated content and request authorization, not merely CORS. The current handler's token is optional and disabled in packaged builds.
- The origin changes from Wails to MyGo, so any browser storage keyed by origin must be checked. Check bundle identifier, paths, signing, distribution, launch/build scripts, reader mode, preview links and platform-specific assumptions.
- MyGo describes itself as pure Go and requires Go 1.27.3+ in its [README](https://github.com/egoist/mygo/blob/cbee0b218286ab533aa005ac621a4e34ab6b1422/README.md); that is a framework claim, not proof the complete Felicia dependency tree cross-compiles without cgo. Assess maintenance and version stability separately.

## Projects using MyGo

These are repository/source observations, not installations, independent reliability assessments or proof of user adoption:

- [DayBee](https://github.com/nexmoe/DayBee/tree/8ff28dc916ae73fb1fb746e938e13ee256f868eb) is a Go/MyGo recording and transcription app, with a desktop frontend and macOS/Windows downloads. Its [Electron-to-MyGo verification report](https://github.com/nexmoe/DayBee/blob/8ff28dc916ae73fb1fb746e938e13ee256f868eb/docs/migration-verification.md) is useful migration evidence: on 2026-10-18 its visible UI, clean-machine, signed-update and platform manual acceptance remained incomplete; local measurements and automation did not prove them. It used MyGo 0.3.4, not the current version. Its first Electron upgrade needed manual installation. Do not transfer its bundle-size numbers to Felicia.
- [MonitorBar](https://github.com/Binaryify/MonitorBar/tree/4aaa7691b14ba79b8573340fa46160e38ac01c42) is a macOS/Windows monitor utility using MyGo's native Go UI. Its README describes platform-specific OS integrations and CI packaging; its macOS app is unsigned. This demonstrates a real project, not Svelte/webview compatibility.
- [Kero](https://github.com/egoist/kero/tree/b057c594ca4d115b5d5eabea84beee669074ffe5), by MyGo's author, is a desktop agent terminal with releases. MyGo's [showcase](https://github.com/egoist/mygo/blob/cbee0b218286ab533aa005ac621a4e34ab6b1422/website/src/showcase.ts) identifies it as native UI. It is not independent evidence of framework maintenance.
- The showcase lists [Liubai](https://liubai.echovic.com) as a web-mode Markdown editor and [Clipnest](https://clipnest.echovic.com) as a web-mode clipboard app. They are promising comparators, but only their showcase entries were inspected; their implementation and distribution claims remain unverified.

Additional projects can be found through the [community showcase issue](https://github.com/egoist/mygo/issues/533). A GitHub code search for `github.com/egoist/mygo` in `go.mod` also returned multiple repositories; an import alone does not establish shipping status or practical maturity.

## Direct cut-over acceptance

The owner selected a direct cut-over to MyGo v0.7.2; Liquid Glass is optional. Acceptance requires: (1) desktop builds with MyGo pinned and no Wails runtime; (2) existing admin and reader UI, JSON mutation requests, file/folder picker cancellation, compilation and published-only preview work; (3) privileged operations remain inaccessible to other processes and untrusted pages, with no authoring TCP listener; (4) macOS titlebar controls and dragging work without requiring Liquid Glass; (5) desktop headless and browser checks, project gates, and real macOS native-window acceptance are reported separately. Preserve existing workspace and publication data. Changes to dependencies, frontend chrome, desktop composition, tests, packaging and related documentation are in scope; release and deployment are not.

## Cut-over handoff (incomplete)

On `feat/desktop-studio-scaffold` at base `8d512df6b467fccaeb6e7cc749524e2f0f7ffcde`, the working tree has an uncommitted direct MyGo 0.7.2 cut-over. Do not treat it as accepted or ship it. MyGo requires Go 1.27.3; golangci-lint was raised to 2.15.0 after 2.13.1 failed to read the newer export data. With those pins, `make check` passed. `make e2e` built both frontends and the test composition, passed the Go e2e tests and 12 Chromium tests, but failed to finish: WebKit's browser launch timed out after 180 seconds and the overall task was killed after 900 seconds. The browser gate has not passed. A standalone 15-second WebKit launch also times out outside Felicia; Node also timed out, and a freshly installed isolated copy of WebKit revision 2336 failed identically. The cached app's signature verifies. At the time of failure `/dev/console` was owned by root, no user GUI domain was available, and macOS logs showed failed pasteboard and WindowServer connections. An absent graphical login is the leading hypothesis, not yet a proven cause: log into the Mac as the owning user and repeat the standalone launch, then the full gate. The check's `uv run` also modified `uv.lock`'s exclude-newer span; that incidental change was reverted.

Tracking issue: [#178](https://github.com/azusachino/felicia/issues/178). Next: resolve the WebKit launch failure and rerun the full browser gate; finish security review of custom-scheme navigation and request origin enforcement; verify the real native window, JSON writes and pickers against isolated synthetic data. The new protocol guard and frontend detection have not received native runtime acceptance. The Wails-dependent docs and integration references still need updating. No commit or PR was created; the cut-over is present only as uncommitted changes on this checkout.

## Suggested spike

In an isolated experimental branch, pin a MyGo revision and reuse `DesktopHandler` on the `mygo` scheme. On macOS, demonstrate embedded UI, API GET and JSON POST, local file and folder dialogs including cancel, reader/admin isolation, a compile and read-only preview, window dragging and native visual behavior. Check that no privileged TCP listener exists and that hostile or navigated pages cannot mutate data. Then run the project's relevant Go and Playwright checks plus native visual acceptance; current `make e2e` does not exercise the native window or dialogs. Compare the maintenance and measurable benefits with Wails before committing to a migration.
