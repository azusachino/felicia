# ADR 0017: SQLite-First Storage with Optional PostgreSQL

## Context

Felicia is primarily a single-user personal travel journal deployed locally.
The current PostgreSQL/PostGIS stack is useful for a future hosted or larger
deployment, but it adds operational weight to local development and workflow
verification.

## Decision

SQLite is the default local and single-user storage provider. PostgreSQL and
PostGIS remain supported as an optional provider behind the same core
contracts. SQLite stores canonical geometry in a portable serialized form and
performs application-level route operations; PostgreSQL may use PostGIS for
provider-specific spatial acceleration.

UUIDv7 is generated by Go and stored in provider-native representations.
Draft persistence may contain nullable publication fields, while runtime
validation remains lifecycle-aware and rejects incomplete publication.

## Consequences

Local setup and disposable end-to-end tests become simpler and safer. Provider
conformance tests are required to prevent SQLite and PostgreSQL behavior from
drifting. PostgreSQL-specific spatial queries cannot be part of the runtime
contract and must remain inside its provider.
